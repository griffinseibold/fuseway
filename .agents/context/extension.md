# @fuseway chat participant

`extension/`: a VS Code chat participant. It routes each request itself instead of letting a chat model decide when to call tools. `router.js` has the logic and no `vscode` import (tested by `test/router.test.mjs`); `extension.js` is the VS Code layer. Built into a VSIX by `extension/build.mjs` (a stored zip, no vsce) and installed with `fuseway extension`.

## Roles and routing modes
- **Every request gets a role** (`roles.js`, catalog `roles.json`; tests in `test/roles.test.mjs`): `/plan` etc., else a follow-up keeps the previous turn's role (from reply `metadata.role`), else the earliest phrase match across roles, else a `starts` role (Explainer: opens with a question word and has no edit verb), else the default (Builder). "Go ahead" after a read-only role switches to Builder but keeps the backend, so the session resumes. Free: no model call.
- **The role applies in every mode:** its instructions are prepended to the prompt (`roleNote`) and `edits: false` runs the agent read-only. `fuseway.allowEdits` off still wins.
- **`fuseway.routing`:** `roles` picks Claude or Codex from the role's `prefer` and runs it with the role's `claudeModel` / `codexEffort` (`pickBackend`, `roleOptions`). It skips the classifier, decisions and the background learner, whose paid Haiku tests would spend quota for someone who never set up a local model. `local-first` is the pipeline below, with the models from settings. `auto` (default) is `roles` until `~/.config/fuseway/local.json` exists.
- **In roles mode, availability:** `router.installed()` checks for the `claude` and `codex` binaries. A missing one, a provider within its reserve, or a usage-limit error hands over to the other. `fuseway.frontier` other than `balance` wins over the role's preference. A PDF or image goes to Claude.
- **Doctor:** the local model, its Codex profile, and the second CLI (once one is signed in) are `optional`, so a fresh extension-only install gets no startup notification.

## Local-first: per request
0. **Structural rules** (`applyRules`) decide on their own: a short follow-up stays with the frontier backend that answered; 2 failed local tries escalate; so do size over half the local context, a pinned path, and more than 2 files. Attached files come from `request.references`, minus the instruction files VS Code attaches to every request (ids `vscode.instructions…`). An attached PDF or image pins Claude Code, which reads them natively; the local model reads text only.
   **Attachments reach the agent as paths.** The backends get only prompt text, so `attachmentNote` appends each attachment's absolute path. Uploaded or pasted attachments arrive as bytes (`ChatReferenceBinaryData`: `mimeType` plus `data()`), not files, so they're written to a `fuseway-attachments-*` temp folder first. Folders outside the workspace go to Claude as `--add-dir`. Before this, attachments only informed routing and never reached the model.
1. **Catalog rules** (`rules.json`, 79 entries; a repo adds or disables entries in `.agents/routing.json`). Qwen gets the whole catalog as a fixed system prompt, which llama-server caches: ~3K tokens, 4 s cold and ~1 s warm. It returns matched rule ids, each `strong` or `weak`, plus a LOCAL/FRONTIER tier, constrained by `json_schema` to real ids. A strong frontier match goes frontier. A frontier keyword or a weak frontier match goes to Haiku with that rule's description as a hint, so a keyword never goes local on Qwen's word alone. Then a strong local match or local keyword stays local, and otherwise Qwen's tier decides, with Haiku checking FRONTIER. If the local model is down, everything goes frontier. Haiku runs as `claude -p` with a one-line system prompt and no tools, in a temp dir: ~1K tokens instead of ~38K.
2. **Pick a frontier backend** by headroom: 1 minus the larger of the 5-hour and weekly utilization, after a reserve (`fuseway.claudeReserve`, default 0.2; `codexReserve`, default 0). Signed in with a plan, headless `claude -p` draws from the same windows as your interactive sessions (Anthropic paused the separate Agent SDK credit announced for June 15, 2026). The reserve keeps part of Claude for you; it yields Codex as soon as Claude is inside its reserve. Claude's `stream-json` output includes a `rate_limit_event` with `unifiedWindows.five_hour.utilization`, saved to `~/.local/state/fuseway/claude-limits.json`. Codex writes `rate_limits.primary.used_percent` into its session files under `~/.codex/sessions`. A window whose `resetsAt` has passed counts as full.
2b. **Skills** (`skills.json`): the first entry whose phrase matches and whose skill is installed in the repo's `.agents/skills/` appends "read `.agents/skills/<name>/SKILL.md` and follow it" to the prompt, and shows `skill: <name>` in the trail. A `route: frontier` skill (security audit, multi-model review, blast radius, API design) raises a local route; a forced backend keeps its choice. Matching is free (phrases, no model call), so keep phrases specific. Repos add entries with `skills` or remove them with `disable` in `.agents/routing.json`. "Second opinion" and "multiple models" go to pstack's `interrogate` rather than the claude-octopus or claude-consensus plugins, which need a plugin install and send code to more providers.
3. **Run** an agent CLI in the workspace: local = `codex exec --profile local`, `claude -p --output-format stream-json` (Sonnet by default), `codex exec`. Edits are on by default (`acceptEdits` / `workspace-write`).
4. **Follow-ups** resume the backend's own session (`--resume`, `codex exec … resume <id>`; options must come before `resume`), and get a transcript of turns other backends handled since. Session ids ride in each reply's `metadata`. The local model never resumes: its sessions fill with tool output, and one that grew to 2.8M tokens failed at 65K on its first call. It gets the last 3 turns, clipped, instead.
5. **Fail over**: a usage-limit error from Claude or Codex retries once on the other. A local run that errors or comes back empty retries on frontier. Neither happens when the user forced a backend.

## The learner
`learner.js` (no vscode import; tests in `test/learner.test.mjs`) keeps one event log, `~/.local/state/fuseway/learning.jsonl` (`FUSEWAY_LEARNING_LOG` overrides it). The event types are decision, router, outcome, label, escalated, agent, bench and switch, and scores are recomputed from the log.
- **Candidates** are `cascade@<local model>` (the default), `local-only@<local model>` and `haiku`; `ROUTERS` lists them. `classifyWith(name)` runs one and measures its paid tokens and time. `freeShadows` reads other candidates' answers off a cascade run: one that asked Haiku shows Haiku's answer and that local-only would have said frontier.
- **Outcomes** come from the next message (`outcomeFromNextTurn`: a failure phrase or switching backends is a failure, moving on is a success) or from `onDidReceiveFeedback`, which wins. **Labels** come only from local answers: success means local, failure or escalation means frontier.
- **Score:** recency-weighted accuracy (half-life 7 days; test cases count half), minus 1 point per 1K paid tokens per decision and 0.5 per second. A switch needs ≥15 recent weighted results, a 3-point lead, and 24 h since the last switch, all in `POLICY`. A router tied to an unconfigured local model hands over right away.
- **Background `tick`** runs 5 s after a turn when idle. It fills in missing router answers on the last 2 days of decisions, then gives thin candidates cases: this machine's labeled prompts first, then `route-cases.json`. Paid work stays within `fuseway.learning.dailyPaidTokens`. It stops when a request arrives or the local model is down (nothing is recorded while offline). At most 6 jobs per tick.
- **Live check (2026-11-21):** one request produced a decision with local-only's answer free, a background Haiku shadow (925 tokens), and 5 test cases for the cascade (5/5, free); `/stats` rendered.
- **Limit:** frontier-served requests give no label, so over-escalation is only measured on test cases and on Haiku shadows of local answers.

## Setup from VS Code
The VSIX bundles `bin/fuseway.mjs`, `template/`, `.agents/fusion`, `.agents/skills`, the refresh task and `local-llm/` at their repo paths. `extension.js` runs the CLI with `process.execPath` and `ELECTRON_RUN_AS_NODE=1`, so VS Code's own Node runs it. On startup (`onStartupFinished`) it runs `doctor --json` and shows one notification if anything needs fixing. The commands are Check Setup, Set Up Local Model (`model --install` in a terminal) and Add to This Repo. The startup notification's Set Up button runs every failed check's `run` command in a terminal named "Fuseway setup".

## Measured (2026-11-21)
- Routing, `node extension/route-eval.mjs`: 67/67 across three sets. That's 16 written alongside the keywords; 31 phrased without keywords, several of which paraphrase catalog examples; and 20 fresh cases unlike any example, including a trap ("change the copyright year"). Haiku was consulted 2 times (2K Claude tokens), at 1.15 s per decision. Two earlier misses came from topic keywords deciding alone (`backup`, `copyright`). That's why keywords now only force a frontier check, and why the catalog keeps keywords to words that nearly always mean risk.
- Real chat turns: a JSDoc request went local (12.9K tokens, 19 s). A concurrency question went Qwen FRONTIER, then Haiku FRONTIER, then Claude (46K tokens, 6 s). A forced `/codex` used 74K tokens on a one-sentence answer, because Codex read the context index and the file first.

## Gotchas
- **Updating needs a reload.** VS Code activates a newly installed extension right away, but an update loads only after *Developer: Reload Window*, which also restarts other extensions (including Claude Code). To test changes without a reload, install a copy under a new extension id and participant name.
- **A reply is always the end of the run.** The agent CLI has exited by the time anything is shown, and nothing keeps working after a reply. Agents (especially the local model) sometimes end on a promise ("Let me debug…"), which reads as if work were still going on. `unfinished()` catches a last sentence like that and adds a "Stopped before finishing" note. Every footer starts with "Done" or "Stopped early", then "no agent still working". `continue` resumes the same backend's session.
- **Reloading doesn't rebuild.** A reload runs whatever VSIX is installed; source changes need `fuseway extension` first. Every request writes `.fuseway/debug/last-request.json` (installed build, VS Code version, each reference's id, type and scheme, no contents), which is the first thing to read when a change doesn't seem to take effect.
- **VS Code also sends the file open in the editor** (`vscode.implicit.file`, "User's active file"). It's mentioned to the agent as open, not as attached, and doesn't count toward routing. A PDF attached from outside the workspace arrives as a plain `file:` URI (VS Code 1.146).
- **`code chat -m ask "@fuseway …"` always goes to the main VS Code instance,** even with `--user-data-dir`. It's useful for end-to-end tests. Each call opens a new chat, so follow-ups can't be tested this way.
- **Replies can be read from disk.** They're saved under `~/.config/Code/User/workspaceStorage/<id>/chatSessions/*.jsonl`, written lazily, sometimes a minute late.
- **VS Code attaches instruction files to every request** as references: `AGENTS.md`, `CLAUDE.md` and `copilot-instructions.md`, `kind: promptFile`. Counting them as attachments sent a one-line JSDoc request to Codex; they're filtered out now.
- **Not verified:** whether VS Code's chat view works for `@fuseway` without a GitHub sign-in, and the local-failure and usage-limit retries in a live chat (only the decisions are unit-tested).
